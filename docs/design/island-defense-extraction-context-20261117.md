# CAS 岛屿攻防与搜打撤：跨聊天上下文

整理日期：2026-11-17（北京时间）。用途：让另一个聊天不依赖旧聊天记录，也能继续和用户讨论两种模式、经济与海陆协同的设计。

**当前任务是继续设计交流，不是自动启动重构。** 先理解下面的用户要求，讨论未定问题，再按用户后续指令推进。文中的“用户要求”“设计建议”“开发记录”分别标注，不能把建议或样板当成已确认、已完整实现的游戏。

## 1. 项目与核心体验

- 工作区：`D:\desktop\cas`。Godot项目，存在Rust原生/WASM规则核心。Windows已装Godot、Blender；用户有Tripo网页会员和API额度。
- 游戏背景是前文明崩溃后的末日水世界：废墟、淹没都市、海怪、流浪战帮、人类幸存者、舰娘和稀有战术部队MCP协议。
- 舰娘是一个女性人格，舰装形态能上岸，战舰形态是真战舰，舰上许多同外貌身体共用同一意识，承担不同海员工作。战术部队也是一个女性AI人格控制多个女性外表机器人身体，世界观编制上限约1000–6000；不等于每局需要渲染几千人。
- 希望获得的体验：侦察目标 → 选择舰队与投送 → 海战/抢滩/空降 → 步兵、装甲、舰炮与航空协同 → 抢物资或关键目标 → 判断继续深入还是带收益撤回 → 建设、整备、养成。
- 用户最不满意：节奏过快或无聊空等、移动不自然、兵种同质、坦克通吃、粗糙且比例失调的地形、按钮和数字太多、教学无法让人自己玩明白。

## 2. 已明确的设计底线

### 模式边界

1. **历史战役保持CAS原汁原味的拟真模拟**：舰队、阵位、距离、航向航速、环境、规则表值与特例不能为了平衡乱改。原始PDF和参考工程不修改。
2. 原创剧情、岛战、搜打撤允许为游戏性改编，但必须显式版本化，不能给旧航次、历史战役静默换规则。
3. 原创模式敌人应有可读血量、攻击方式/预警和数据信息；仍需明确发现/可见性规则，不代表自动AI可以偷读后台隐藏实体。
4. 家园、岛战、搜打撤和海图最终共享权威地理/米制坐标/设施。海图通过LOD与符号简化，而不是缩岛、放大楼或压缩舰队距离。

### 设计与操作哲学

- 操作以**拖动**为核心，少组件、少常驻文字，多图标和素材；需要输入数量时用滑块/预设。
- 海图和陆图可互换主图/小图；底部展示海军、战术连队及航空组件。战术牌写人格名和完整编制番号，北约符号带旅X/师XX等规模信息。
- 卡牌和地图上的实体都可拖动指挥。载具默认拖动移动，攻击和指定炮向有清楚区别；技能可拖目标，或点技能再点地图。
- 放大地图不能让人物反而变小；脚底、图像、选中圈、拾取、真实实体位置一致。人物不能倒着走、闪现或被动画挪离实体。
- 需要从简单到复杂、按真实动作推进的手把手教学：海战制海、岸边卸载、步坦协同、舰炮支援、空输、防空、搜索与撤收。不能点几次“下一步”就算会了。
- 玩家可以一键全程托管，也能随时手动干预；独立载具和连队内置协同不能依赖总托管开关。

## 3. 美术、地图与设备方向

**用户已认可的方向**：从获批的三维海岸Demo出发重建，必要时放弃原来的粗糙地形。明快、较鲜艳、偏动漫，但有具体废土细节；有动态水波、推进/破碎海浪、云影和变化天气。战场地理必须程序生成/模拟，固定图片只可当菜单原画。

只有人物身体/步兵用2D动画；建筑、树石、登陆艇、坦克、两栖车、火炮、直升机等用真3D。优先复用认可素材或下载许可清楚的免费模型，其次Blender，最后Tripo补缺，不能把“有会员”当作必须付费生成一切。

岛屿需要真实纵深与起伏：有限可登陆沙滩、悬崖、高低地、沼泽、河流、森林、灌木、道路/十字路口、墙门、壕沟、废弃建筑和淹没设施。地形应影响可达性、移动、视野和射界；不能只画装饰。建筑、道路、人车尺度需同框目检。

目标中端手机，必要时PC/手机不同细节档；手机实机帧时间和内存尚不能用桌面演示替代。保留尸体状态，远处可降动画频率、合批和LOD，不直接删掉真实战斗单位换帧率。

风格参考入口：`CAS-Land-Art-Demo.cmd`。已认可对照图：`D:/desktop/cas/artifacts/coast-v2-20261116/final-20261116-132456/screenshots/crossroads.png`。样区只是样区，不能当作全模式重构完成。

## 4. 岛屿攻防：用户已经明确的想法

### 建设与自主布防

- 家园生产通用建筑材料、粮食及其他经济/养成物资；生产缓冲溢出进岛仓。
- 玩家可在一定范围内改造地形、布置建筑与防御。生产占地与军事占地存在取舍。
- 防御塔要多样且有反制：机枪、反坦克炮、重反甲、迫击炮、近防、对海岸炮、防空、雷达等；地雷、水雷、墙、壕沟、滩头阵地与军营驻军可组合。
- 防御塔和防御体系受有限预算约束，岛屿等级决定容量上限；不能靠无限堆塔解决。
- **防守重心由玩家决定**，不要强制每个岛固定三道防线。可以重岸防、重工业保护、重核心驻军或重机动反击。
- 岛随等级成长，扩大的是实际可用空间和战术纵深，不是只调大镜头。

### 海陆相互创造机会

- 海军和敌留守舰队先真实交战；留守舰需要起锚后出动。
- 强对海岸炮使攻击舰队不能随意靠近持续支援；陆军可侧袭摧毁岸炮，让海军获得更好炮援位置。
- 不能做“陆军没完成按钮，海军就禁用”的假锁；真实远距轰击仍可行，但受观察、散布、射界、装填、弹药、驻防舰等代价制约。
- 反甲炮高单发、慢装填、小范围，擅长打车；普通陆战队靠人数、烟幕、压制和绕侧清除炮位。装甲有威力，但需要步兵打开道路和处理任务。
- 航母/舰炮支援通过可拖动组件调度；有真实射击轨迹、口径差异和力量感。企业的127mm炮不能表现得像战列舰主炮。
- 本地无损攻防演习：用自己的攻击队打自己的岛，不扣真实油弹/体力，不损坏真实设施，不产生可刷取奖励。
- 要有侵岛/被入侵记录和回放；先NPC岛，再讨论真人异步入侵的最终规则。

### 节奏

用户希望**一场标准岛屿攻防约15分钟**，现在的运动和交战常常太快、简陋，没有足够操作空间。按正常1×的完整行动计算，不含菜单、暂停和剧情阅读；不同难度/教学不必强行相同。

上一轮建议把过程组织成侦察/制海、建立登陆条件、主攻/机动反击、争夺/装运/撤收。它们可并行、提前或跳过，并非必须依次走三层防线。不能仅靠减速和扩大地图凑时长。

## 5. 战术部队与载具：不得再理解错

### 编制与武器

- 一个战术人格通常展开2–5个独立连队，每连6–10个女性身体；特殊编制允许例外。每身体有真实碰撞、武器和状态，不画成整齐方阵同步滑行。
- 普通步兵大多携轻武器；专职火箭手/防空手数量有限，不能全连都变成导弹发射器。
- 不同人格即使用同一武器类别，也可用不同型号。精度衰减、射程、射速、点射/连射、弹匣和换弹各有区别。冲锋枪远距衰减大，射手步枪衰减较小。
- 功能部队火力可以弱：203指挥组强化移动/精度/任务；184城市攻坚重甲、每连2霰弹其余冲锋枪；145每连2防空弹手其余步枪；128每连1重狙其余射手步枪并引导炮援；116保障技能是buff，不凭空制造弹药；009是持步枪的战斗工兵，技能爆破。
- 用户曾要求战术身体HP变为旧基准4倍，已进入27人基线；不要每次重构再乘4。伤害/耐久新草案仍需实际TTK验证。

### 投送与持续作战是两件事

| 类别 | 已明确要求 |
| --- | --- |
| 普通陆战 | 任意有资格/舱位的战舰可搭载；船先到近岸，艇只在合法岸边逐人卸载，再向内陆步行 |
| 022重装甲 | 固定重型登陆艇；每连1辆独立坦克+6名持步枪身体，上岸步坦协同 |
| 103及其他两栖车 | 同一独立车体渡海和陆战；乘员可上下车；水中慢、陆上快；不能爬所有悬崖 |
| 自行炮087 | 有独立自行火炮；随行身体只持手枪自卫，不能跟着远程攻击命令冲锋 |
| 运输直升机空突 | 直升机主要负责投送/回收，不因此免费变成武直 |
| 武装直升机027/006 | 飞机与随行身体分别有HP、武器和命令，飞机也能装卸人员并持续作战 |
| 伞降088 | 5连×10身体，真实开伞/下降/着地，空中脆弱；运输艇用于撤离，不能当作入场工具 |

装甲部队由APV/两栖攻击舰/航母等合格载舰承运；空输/伞降由LHA或航母。固定投送工具不能又让玩家随意选艇。车内身体不同时在地面射击/占点/搜索。

每连坦克、两栖车和武直是独立实体，不是一个身体的替代皮肤；步兵全灭后车辆仍能指挥、索敌、开火和撤回。步兵在真实车体后掩护、探身射击、受压回掩护，不能用屏幕挪位或无条件光环冒充遮挡。

**历史表述冲突已厘清**：用户早期描述006有6架武直，后续明确“每连一架独立武直”，项目治理已按后者覆盖；当前006为1连6身体+1机。别把早期6机重新当成当前默认。

日常要本人SD多帧互动，战斗要行走、瞄准、真实开火、换弹、受击、技能、上下车/伞降和多种倒地动作。尸体保留并贴真实坡面；车辆有转向、履带/轮胎/旋翼、炮塔、后坐和真实炮口效果。

## 6. 搜打撤：已有诉求与旧版经验

核心是“再深入一点的预期收益”与“已经装船的收益及撤离风险”之间的选择，不是绕着海图无事航行，也不是清空所有敌人才能走。

### 世界与目标

- 程序生成不同海域、岛、道路/岸段与目标。用户要求有淹没楼群、水下设施、废土遗迹等，不是纯自然小岛。
- 敌人除按出征战力匹配的敌对舰队，还包括俯视海怪和陆地怪物/机器人，攻击有可读预告、不同动作与反制。
- 参考《绝地潜兵》的任务组合思路：主任务、临时/可选任务、可绕开的Boss和撤离压力；不要仅增加怪物数量。
- 用户要求时间越晚威胁越高；波次和Boss应有预警、数量/性能上限，保留止盈撤离机会。
- 携带陆军时增加只有陆军才能做的岸上遗迹、回收协议、救援、重启中继等任务；陆军行动属于同一航次，不免费复制一套部队。

### 出航、弹药、打捞与货舱

- 可选多个编队；携带运输舰、少装炮弹或DD少带/不带鱼雷，应真实腾出运载空间，同时失去相应战斗库存。
- 炮弹/鱼雷有类型差异，鱼雷为即时装填和备用库存，不能退回回合制。具体装填秒数是版本参数，不把旧表写死给新版本。
- 打捞有搜索进度、逐件揭示。可出售物、可拆包物单独标注并有独立美术，既有设计包含净水滤芯、旧相机、医疗箱、记忆匣、教团芯片等。
- 货舱是格形空间，物品有形状、重量、价值；拖放要有吸附、旋转、位置/容量预览和失败反馈，可一键紧凑整理。不能搜索完自动把全部奖励写进钱包。
- 基地仓库、当前编队货舱分开，能一键处理明确的可售杂物，但不能误卖养成/任务物。
- 搜索使用真实模拟时间，靠近/减速等条件要可见；整理单机货舱可暂停，离开恢复原运行状态。

### 全程自动指挥

用户明确想要：进入后能自动接任务、打捞、评估挑战、装载与撤离，全程无需人类逐步点确认；但手动随时可接管。

评估要读真实血量、炮弹、鱼雷、燃油、舱位、时间、已知威胁和已携收益。不同策略可谨慎/均衡/进取。不能搜完第一点就默认撤，也不能搜完第一点卡住。

多编队要分别分配遗迹/任务、支援与撤离，别全挤同一坐标。撤离应先真实重整紧密但安全的队形，分配靠泊位置，预留转向空间。陆军要真正回到合格接驳舰，不能删除岸上身体当作成功回收。

手动整理货舱不应自动关闭航行托管；真实航行/攻击命令的接管规则要明确。卡住时显示原因、退避、换路或换目标，不能后台不停提交同一个非法指令。

**旧合同不等于最新统一实现**：早期搜打撤v4有8/14/20体力、四地貌、快速航行等参数；两栖远征v3又有不同海图尺度、投送距离、旧高地模型。新的真实尺度岛战/经济方案不能不经检查照抄。旧合同曾仅允许一个搜索通道，多编队并行靠近、轮流搜索，不能将它误称真正多点同时搜索。新设计可讨论改造，但要版本化、实测任务收益与回放。

## 7. 两种模式共用的出征经济

**用户最新明确提出：**

| 项目 | 期望的成本/收入 |
| --- | --- |
| 舰队搜打撤/侵岛 | 燃油、体力、补充实际弹药；船损用通用建筑材料维修 |
| 战术部队 | 出击固定消耗油、弹、粮；重损另用建材恢复 |
| 家园 | 生产建材、粮食及相关资源，溢出进岛仓；生产与防御争土地 |
| 撤离 | 真正带回的物资用于出售、拆包、建设、养成和下一次整备 |

后续设计需把成本按**选中的连队**报价，不因拥有整个人格就收满编费。固定弹药包和每发射击不能重复扣同一钱包。舰娘/persona、等级和外观不因损失永久删除，消耗的是可恢复的身体/车辆与整备。

要保留低风险恢复途径和保护库存，防止一次失败后油弹耗尽、工厂坏了、修不起而无法继续。测试账号满资源不能替代普通新号经济测试。

**上一轮助手提出、仍未由用户逐项确认的建议：**

- 五种主资源：油、弹药补给、粮食、建材、银币，体力独立；元词/抽卡券沿既有征募系统，不拿来强制维修。
- 设施缓冲满自动入岛仓，总容量满暂停生产；不暗中销毁旧库存。
- 塔、工事、驻军和留守舰都占预算；攻击也计海陆空总容量，自带投送不重复计费。
- 海陆反制以真实射界/可达/弹药体现；远射昂贵但可行，不能无敌岸炮或界面硬锁。
- 标准攻防12–18分钟、普通身体1.5–2.4m/s；具体体力、产率、技能秒数、维修费和收益倍数全部是原型起点。
- 原型HQ1–5防御容量60/100/150/220/300，改地面积10%–25%；HQ3先试守150、攻180。不是已定案经济，也不能把不同阵容漏算海军后声称同预算。

完整三档收支试算、27人格和55武器草案见第10节。应讨论后再采纳，不直接整表覆盖。

## 9. 在新聊天优先讨论什么

建议按以下顺序继续，每次明确哪些已决定、哪些保留备选：

1. **两种模式的胜利/撤收区别**：侵岛必须夺HQ，还是允许打仓库即走？搜打撤主任务和纯搜索各有什么回报？陆军未回收如何结算？
2. **15分钟的玩家决策密度**：海战制海如何与登陆并行，首波登陆/援军/炮援窗口在哪里，怎样避免海战流程卡死或长途空等。
3. **攻守总预算与兵种反制**：舰队、陆军、航空、塔、运输如何统一计费；纯装甲在哪种布局强，普通陆战在哪些任务不可替代。
4. **地形与建设自由度**：自然岛与生产土地、有限滩头、道路/桥/壕沟、高地/观察站、可改造范围；如何既自由又不封死通路。
5. **经济和失败恢复**：新号/中期/满级出征报价、实际战损、净收益、离线产能、保护储备；岛被抢是否停产、修多久、如何防止反复抢同一份库存。
6. **搜打撤局内变化**：不同地貌的路线抉择、陆海可选任务、预告Boss、时间升压、多编队分工；不要单纯刷更多怪。
7. **操控与托管职责**：拖拽预览、炮向/移动区分、搜索装载、技能、地图切换；手动任务持续到完成/取消，明确交回托管，避免AI立刻改派。
8. **先验证最小样板**：修流程后用三张岛/数种阵容验证，再扩全兵种和系统。不以增加更多武器、CG、塔名替代可玩的战术循环。
