# 陆地场景重构、装甲制衡与模型制作计划

日期：2026-11-15。状态：**下一阶段设计交付，尚未实施**。

## 1. 本次决定

下一步先做一个能实际游玩的海岸样区：自然沙滩通向坡地、道路、居民点、工厂与防御阵地。它既是三维美术样板，也是装甲、陆战队、登陆和家园生产的共同原型。通过样区后，才扩展整个岛屿和批量整理模型。

推荐长期路线是**程序化三维地形＋模块化环境＋现有本人SD角色**。保持目前斜俯视和拖动操作，不在同一阶段增加自由旋转镜头或把全部角色重做成三维。三维源模型还可以烘焙成二维散件，作为过渡或低配备选；是否需要这种额外产线，由样区实测决定。

素材取得顺序固定为：**项目已有资产 → 免费且许可明确的模型/材质 → Blender改造及精确建模 → Tripo补原创缺项**。不因为已有额度就先生成普通树、普通房屋和整座岛。

用户已确认中端手机优先，电脑可使用更高效果档；同时拥有Tripo网页会员与API额度。具体手机型号、Blender可执行文件与版本、API实际可用版本/额度在实施首步核实，不再把这些信息缺失变成重复确认。

## 3. 美术方向与比例

采用**明快、带动漫色彩关系的战术海岛**：自然地表和可信建筑体积，配本人SD；比用户提供的战术游戏截图更鲜艳、通透，保留材料层次，避免灰暗滤镜、纯色玩具块和平均撒树。

五张参考已逐张目检，原始研究副本见[参考目录](../../artifacts/island-style-reference-20261115/manifest.json)。借鉴的是连续地面、建筑道路关系、树林群落、接地阴影和远近空间组织。这五图未直接展示海岸，以下海岸设计来自用户历次需求，不冒称从图中核实。

| 层次 | 制作目标 | 直接否决的效果 |
| --- | --- | --- |
| 海岸 | 海湾、岬角、岩岸、崖岸、局部沙滩；浅水—湿沙—干沙—背滩连续变化，泡沫贴实际岸线 | 等宽黄色环岛带、规则多边形饼、细锯齿替代大尺度岸形 |
| 高地 | 连续坡面、山脊沟谷、坡脚堆积；崖壁有方向和疏密变化 | 复制多个相同台子、垂直墙上贴道路、视觉缓坡而实际不可走 |
| 地表 | 草/土/沙/岩共享色调；大色块、中尺度混合、微细节分层，按米制统一纹理密度 | 模糊绿毯、均匀噪点、远景闪烁、每种素材各自光照 |
| 聚落 | 沿路成组的浅墙红瓦/灰顶房屋、庭院、入口、装卸空间；工业与农业各有组织 | 一栋插画楼孤立贴草地、全岛一个格网、无用途的密集杂物 |
| 植被 | 林地—林缘—灌木—开阔地过渡，树形至少两类，避开入口/道路/卸载点 | 等间距同树、透明树叶层层叠满屏、跨高差巨树 |
| 战斗 | 工事轮廓和火力方向清楚，敌我/选中/落点可读，建筑遮挡采用轮廓或局部处理 | 美术盖住命令标记、塔像普通摆件、炮弹被烟完全吞掉 |

环境、车辆、建筑用米制建模。人物物理半径、武器范围与SD可读性显示分开登记；沿用认可的SD比例基准，不把SD的可读性高度当真实人高，也不继续靠任意放大楼/车补错镜头。建立同框标尺板：真实建筑门洞、层高、道路、艇、坦克、步兵实体与SD外观，近中远三档检查。新三维场景的人物脚底、选中圈、载具中心和弹道起点必须共用实际实体位置。

当前[陆战高地截图](../../artifacts/island-war-v4/presentation/visual-reviewed-final/v4-terrain-highland.png)仍明显是大块平顶与重复侧壁，树石零散，建筑和大面积路网缺少共同密度；[家园近景](../../artifacts/island-war-v4/presentation/visual-reviewed-final/home-native-base-211d.png)则是各自精细的小建筑落在均匀草地上，功能区和空间尺度欠缺组织。重构优先解决这些整体关系，不能只把单栋楼的面数提高。

操作画面继续遵循少文字、少常驻数字、拖动优先：正常战斗保留一排部队卡、暂停/倍速/托管与海陆切换，详细弹药/装甲/编制数据按选中展开。北约类型与规模标记继续保留；手机用清楚的拖放预览和足够触摸热区，不把电脑版密集面板直接缩小。数量设置沿用滑块。

## 4. 场景与权威空间先行

先定义一份家园、陆战、海图、AI和回放都能读取的空间合同，再分工做地形与模型：

1. 米制XY、权威高度/坡度查询、海底深度、岸线和岸型；地形生成版本与快照/稳定摘要。
2. `landing_zone_id`、区段范围、允许的固定投送类型、排队位置、卸载槽位、向内陆的可达路径。
3. 道路/桥/坡道图与按步兵、重车、两栖、空输分别计算的通行；车辆进不去不能因步兵能走而通过。
4. 建筑/农田/战壕真实占地、入口、临岸条件、平整度、施工状态与稳定设施ID。旧120m地址不等于建筑尺寸；建议10m子格只是原型参数，最终按通路精度和性能决定。
5. 地理随机、玩法布置随机、装饰随机分开。换树种/草量不能改变命中结果、登陆区或刷怪。

生成顺序：地貌骨架与功能区约束 → 岛形/高度 → 岸型、水深与河流 → 合法登陆和各类型通路 → 道路/地块 → 玩家建设与工程修改 → 战术地物 → 无战斗效果的装饰。采用有界修复/重试并给出失败原因，不能交付封死出口的随机图。

主岛仍由程序产生，不下载或生成一整座固定岛作为游戏地图。整体山地、河床、沙滩、海面与云不属于Tripo模型任务；模型只提供可重复组合的岩石、崖面、建筑、植被、工事和地标。

## 5. 三维路线与移动端接入

| 方案 | 用途与决策 |
| --- | --- |
| 自有分块高度场＋ArrayMesh | 可控基线。由权威高度生成网格/崖面，道路贴地；镜头移动不重建整岛。先试256m块、8m基础采样，岸线/近景局部细化；这些是实验值，不是规则精度承诺 |
| Terrain3D固定版本 | 免费候选，在同样区比较编辑便利、材质、内存、导出和安卓稳定性。不得用其独立碰撞/噪声取代原核地理 |
| 三维源模型烘焙二维 | 保留同源资产的备选；若三维低档仍无法达标，再比较维护成本，不先维护两套独立地理 |

[Godot程序网格](https://docs.godotengine.org/en/stable/tutorials/3d/procedural_geometry/index.html)适合由数据生成静态/按需更新的地面。Terrain3D目前官方说明支持Mobile和Compatibility，但Android有设备/纹理数组等注意事项；固定插件版本、Godot4.7.2、Windows与Android arm64都实际通过后才选用。参见[官方平台说明](https://github.com/TokisanGames/Terrain3D/blob/main/doc/docs/platforms.md)、[1.0.2发布说明](https://github.com/TokisanGames/Terrain3D/releases/tag/v1.0.2-stable)。不把它“免费且高星”等同于本项目已经兼容。

三维渲染层负责相机射线/地面拾取代理，把结果转换回原核米制坐标；真实碰撞、伤害、视线和路径仍由权威规则计算。岸线、桥头、坡道、入口和战壕保留精确约束边界，粗网格/LOD命中后再经权威高度和合法性复核；验收逐项记录画面落点与实际命令位置误差，不只检查命令最终合法，防止点坡顶却命令到坡底。S0按边界宽度、触摸容错与米制精度登记误差门限。

人物先试Sprite3D并专项检查透明排序、脚底锚点、倒姿和遮挡，切图不移动实体。S1/S2可先把现有同身份人物及装备图接入三维代理，逐类型核脚点和朝向；新车辆GLB排在后续不意味着删除旧装备或给所有部队统一换艇。海陆主图切换共享同一实体ID和命令流，不双开两份独立模拟。

Android分两道门：先出仅渲染样区APK，测图形能力；再打通arm64核心桥与完整单人游戏。实现方式在P0比较Android库/GDExtension等方案，不能继续依赖Windows进程或用旧WebView包冒称Godot移植完成。完整门包括新局、存读、离线、后台恢复、资源释放和核心一致性。

电脑与手机使用同一地图、规则、资产ID、碰撞和回放，区别是贴图上限、LOD、阴影、植被装饰密度、特效与内部渲染分辨率。先测试现有Compatibility和Mobile两档，三维本身不要求Forward+；渲染器能力按[官方说明](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)核对。

## 6. 中端手机首轮预算

以下是制作与压测的**初始警戒线，未由真机证明**。以实际中端Android设备、热机30分钟为验收依据；若无可用真机，只能标桌面/离屏通过，手机验收保留待办。

| 项目 | 手机基准 | 电脑增强档 |
| --- | --- | --- |
| 帧率 | 先稳定30fps；p95≤33.3ms、p99≤50ms目标；预留主线程约16–20ms、GPU约20–24ms，二者重叠不直接相加 | 有余量再开放60fps，不能按编辑器空场景承诺 |
| 分辨率 | 三维约1280×720起测，可降低；UI/触摸热区保持屏幕适配 | 按显示器提高三维分辨率 |
| 纹理 | 常用512–1024，少量共享2048；压缩+mipmap，禁止批量4K | 主设施可用更高纹理，但共用原始源资产 |
| 内存 | 整个进程常驻约500MB、峰值650MB先作告警；纹理约128MB、网格/渲染目标约64MB分项告警。需同时测既有SD/CG/音频，超限再订可达预算 | 记录峰值与释放，不以内存充裕掩盖泄漏 |
| 可见几何 | 环境/载具合计约20–30万三角起测；过载先向10–18万退；不是全资产库总量 | 增加近景LOD与局部细节 |
| 绘制 | 环境不透明约≤120次；含SD、UI、特效全帧尽量≤300次起测 | 放宽但不依赖无控制的材质数量 |
| 光影 | 一盏主方向光；近景有限投影，低档接地影；不逐身体/逐炮弹建灯 | 延长局部阴影距离、增加质量；实时GI另测 |
| 特效 | 起测128–256活跃粒子、4–8个重爆炸；远处简化、表现池复用 | 可增加烟尘/碎屑层次 |
| 分块 | 256m块起测，近景3×3至5×5块精细，远处低模/组块，概览用轮廓与功能区 | 适当延长精细距离 |

树石按空间块、模型和材质组织MultiMesh，不能整岛一个批次；官方指出其内部实例不会单独视锥剔除。Compatibility/Mobile也不能假定享有Forward+的自动实例合批。参见[MultiMesh](https://docs.godotengine.org/en/stable/tutorials/performance/using_multimesh.html)、[三维性能](https://docs.godotengine.org/en/stable/tutorials/performance/optimizing_3d_performance.html)。透明SD裁掉空白，植物尽量裁切或不透明几何，云/水/烟限制重叠；禁止只看面数忽视透明填充和材质批次。

斜俯视的块与LOD按相机地面视野、屏幕像素尺寸和缩放选择，带切换滞后并检查块间接缝；若采用正交相机，不能只按相机距物体的距离切LOD。

27人格与MCP的1000–6000身体世界观上限，不等于手机同屏生成数千高开销动画节点。沿用实际出击连队/独立身体规则，按50、200、500、1000实际实体分别压测；结果明确区分达标规模与压力上限。不得在运行中截断已有合法实体；若新局需要平台规模边界，必须明确登记而非自动吞掉编制。大量身体采用共享图集、分块实例或保留单体ID的轻量表现，每个实体仍有实际状态、位置与指挥能力；表现代理只读权威观察，不参与命中/遮挡/通行裁决。尸体保留航次内全部伤亡记录，近处稳定倒姿、远处分块缓存，返回可还原本人位置/姿势。原核10Hz及倍速推进不得因画面档位改变。

## 7. 免费优先的资产生产

已核实的首轮入口：Quaternius自然包、Kenney住宅/工业/道路、Quaternius遗迹，以及ambientCG材质；Poly Haven只选已免费释放的CC0资产。详细链接、许可与风格风险见[资源表](land-3d-free-assets-and-tools-20261115.md)。

免费不代表直接拼进游戏：每包先选1–3件同镜头比对。Kenney适合灰盒、结构和改造底模，其简化形状不直接代表最终审美；照片扫描资产也不能以原始高模和写实色调直接混入动漫场景。统一顶面/侧面明度、米制纹理密度、粗糙度、色调和光照后才入库。

| 优先级 | 先做的资产族 | 获取方式 |
| --- | --- | --- |
| P0 必须先有 | 岩石/崖面、乔木/灌木、住宅、仓库、码头、道路桥坡、反甲炮与机枪阵地 | 优先免费筛选；精确道路/接口/炮座由Blender补齐，不要求付费生成 |

## 8. Blender至Godot交付标准

每件资产交付项目整理后的可编辑源文件、运行GLB、LOD/碰撞代理、预览与清单，不假定免费包一定提供作者原始工程。Godot推荐glTF；`.blend`直接导入也需要外部Blender转换，因此发布物用GLB更明确。[官方格式说明](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)

| 检查 | 要求 |
| --- | --- |
| 尺寸和轴 | Blender米制；统一前向、地面原点；实际尺寸记清单。不能只按缩略图猜坦克/房高 |
| 几何 | 实际三角形计数、法线/背面、去无用内部面、拆可动炮塔/旋翼/舱门；修薄片和漂浮件 |
| 材质 | 普通物1材质、复杂设施尽量≤2；共享图集；不保留互相矛盾的烘焙太阳影；按Godot档位转贴图 |
| LOD | 参考队列给LOD0，LOD1约40–50%、LOD2约10–20%起测；按轮廓目检，不死套比例；远处组合HLOD |
| 碰撞/战术 | 简单凸体/占地代理独立；桥、入口、卸载面和遮挡数据跟原核，不用生成模型三角汤决定规则 |
| 功能状态 | 设施正常/受损；炮塔/弹道/乘员锚点；动画状态与实体方向一致；载具人车独立、装卸守恒 |
| 证据 | 来源URL/许可原文/作者/下载日期/SHA/修改记录/实际面数/贴图/预览/导入版本；运行资产与原始资料分目录 |

最小工具链是已安装Godot、Blender后台执行与免费资产。MCP不是生成模型的前提；后续确需交互才在官方Blender Lab与社区桥中选择一条。Tripo自动化优先核官方CLI/当前API，不叠装旧alpha插件。详细兼容边界见[工具表](land-3d-free-assets-and-tools-20261115.md)。

## 9. 装甲平衡：让地形、目标和工事形成制约

不先统一砍装甲HP、速度和伤害。保留v4身体基础HP四倍、敌我对称与真实车后掩护，通过以下关系验证兵种价值：

- 重型登陆艇需要宽滩、较好入口、足够卸载/展开空间；遇窄口会排队，但不能永久堵死。两栖车保留水陆一体优势，水里慢、上岸快，只能走实际可上岸的坡面，不能爬悬崖。
- 反甲岸炮优先威胁车辆，高单发、小范围杀伤，有限射界/转向/装填给分散步兵接近机会。当前名义反甲炮参数并不等于这些特性已实现，范围和节奏需要实测。
- 机枪/驻防步兵保护反甲炮，迫击压制聚集，防空限制空突，战壕保护实际进驻者。少量伴随步兵可清孤炮，面对完整阵地和多目标仍需要专业陆战队、工兵或支援。
- 陆战队适合同时清阵地、占领、搜集、进入复杂地形；装甲适合突破、直射火力和保护步兵。两者都不设计成无条件胜利，也不强制每局带固定套路。
- 军舰支援与航空保持真实资源、观察/标定及有限支援窗口，防止免费远程清完全部防线。固定投送载具、人车独立和炮兵身体只自卫继续生效。

第一轮对照至少包括纯重装、两栖、步兵清剿、联合队四种同分数/整备预算编成。记录完成率、带离资源、身体/车辆损失、耗弹、补充成本、用时；不用相同人数冒充相同预算。主要登陆区“2–3处”只是普通岛原型目标，不是所有地图的定数；窄滩不等于给装甲硬设禁用标签。

## 10. 家园经济与自主防守联动

先打通商港、农田/训练供应、工厂、仓库四类最小循环，再增加设施花样。产物接入实际银币、整备和养成消费者；不造只有说明文字的新货币。必须区分`home.resources.credits`岛屿补给与`wallet.credits`银币，迁移不得同名混账；不默认家园被动生产元词。

建筑的经济产能、战场实体、占地/入口、损坏、停产、维修都绑定同一设施ID。升级/迁移/改配方前先结清旧状态，停产时间不按完好补算；离线领取容量与小数余量守恒，重复提交不能多领。倍速战斗不加速家园时间。

玩家自主安排岸防或纵深防御：港口占岸线、工厂需连续平地、农田需成片空间、仓库提供存储，炮位/战壕/道路/军营也消耗土地及建设投入。维护指实际维修、装填、整备或出战成本，首版不新增持续扣负的离线军费。先测可用面积与路网，而不是仍用36栋上限假装山地压缩经济。施工需资源/时间，不能遇袭瞬间把工厂变堡垒。

驻防按稳定连队ID分配区域、巡逻和预备队；同人格可分连驻防/出征但不能复制身体车辆。军营兵力有限，预备队从实际位置出动。战壕只保护真实入位者，有方向与侧后弱点，清剿后可占用。现有区域掩护不能冒称战壕完成。

保留资源损失上限、恢复底线与保留建筑等级的重建方向，避免一次被入侵后无法恢复。首版比较贸易农业、工业纵深、岸防要塞、机动驻军四种同预算布局；升级层数、产率、驻军容量、施工时间、掠夺比例均是下一轮待测数据。

## 13. 版本与发布边界
