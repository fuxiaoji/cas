## 3. 当前实做、样区实做与正式待办

### 3.1 已有正式玩法基础

现有Godot正式显示仍以 `Control/CanvasItem` 二维斜投影为主。家园通过 `island_home_preview` 获取v4原核地理；陆战和两栖海图读取观测中的实际地形。正式v4已发布目录、冻结核与对应合同是基线，共享源码中的并行新部队不能被本轮覆盖。

家园与海岛攻防已有同源地理、固定投送工具、真实人车实体、车后掩护等基础；这不等于已经具备本计划的连续三维高程、完整岸型合法性、细颗粒建设占地和新经济闭环。未在本轮重新实测的原有能力不宣称“已验收通过”。

### 3.2 当前隔离3D样区

`demos/land-art-3d/scripts/coastal_geography.gd` 当前提供：

- `VERSION = coastal-visual-demo-v2`，`AUTHORITY_SCOPE = visual_demo`，明确不属于正式原核权威。
- 米制范围 `[-360,-360,360,360]`，即720×720m的样区；它不是满级家园岛屿。
- `height_at / slope_at / land_distance / biome_at` 共享高度、坡度、岸边距离代理与地表分类；山体、河道、沼泽来自同一组函数。
- `landing_at` 演示普通艇、重型艇、两栖车辆的局部岸段差异。
- `snapshot_header` 明示种子、米制、轴约定及“正式路径/碰撞/AI未安装”。

Demo的建筑、载具、自然物和水面着色可用来审核美术；建筑几何展台不等于生产设施或炮塔战斗功能。本审计只读复核接口，不把正在制作的截图、未运行的测试或未接入的能力记为正式验收。

`landing_at` 当前只组合距离、坡度和岸段access阈值，尚无艇吃水、连续有效滩宽、泊位吞吐、近岸水路、后方通路和拥堵校验。`land_distance` 已如实注释为带符号海岸代理，并非精确欧氏距离场。这些限制适合视觉Demo，正式规则不得直接照搬。

### 3.3 后续正式工作

需要版本化地理原核、可重演生成/保存、统一原核预览、三维显示适配、建设与塔防的语义接线、训练/经济迁移和手机实测。新版本名须先检查登记占用，不能直接替换旧v4存档规则，也不能把Demo版本名作为已发布合同。

## 4. 装甲制衡必须落到实际空间

1. **有限宽度的合法滩头。** 普通艇抵近有效岸段，下船目标经过泊位与占位校验；满载重型艇需要更宽的安全面，不能把车逐个穿过针眼。狭滩产生吞吐和火力风险，但保留改用步兵、火力准备或其他方向的选择。
2. **装甲不能爬崖。** 两栖车辆提高水陆转换能力，不获得垂直攀爬。普通坦克从艇卸载后走合法坡面/道路；两栖车在水里慢、上岸快。运输/武装直升机、伞降的飞越不等于无视落区、航程与防空。
3. **反甲高单发、小范围。** 反甲炮重点打坦克/装甲车，受转向速度、射界、射速、装填和观察限制；不能同时变成清步兵、反坦克、拦飞机的万能塔。分散、多方向、烟幕/压制与支援均应提供可理解的反制。
4. **步兵有清剿价值。** 大编制陆战队负责迂回、进入阵地和清除驻员，工兵用爆破处理工事；不要求玩家只能靠大量身体送死耗完岸炮。机枪、战壕、迫击和预备队会使完整阵地比一门孤立反甲炮更难清理。
5. **步坦协同保持独立实体。** 步兵可以利用坦克遮挡，在侧前方短暂暴露射击，再退回掩护；不能把掩护写成围着坦克固定圈绕。坦克在随行步兵全部损失后仍可选中、移动、瞄准、撤离。无弹药/仅自卫的炮兵身体不因炮车攻击命令冲锋。
6. **地形影响不同对象。** 软土、沼泽、坡度、林地、道路对履带、轮式、步兵和飞行器分别登记。地表外观、寻路成本、实体碰撞和命令预览必须一致；不能只换视觉材质而改变不了策略。

首轮平衡用隔离无损演习：同一预算比较纯装甲、纯步兵和混编；分别测试宽滩、狭滩、带反甲火力的滩头、内陆街区和山谷。目标不是让步兵普遍比坦克强，而是让纯装甲无法在所有地形和工事组合上支配。具体伤害、坡度、宽度和装卸秒数均待实测配置。

## 5. 家园土地、经济与防御的代价

经济继续复用银币、浮材、合金、能源与合法养成物品。账户 `wallet.credits` 是银币，家园 `resources.credits` 是岛屿补给，字段同名不能合并、覆盖或擅自兑换。元词和招募券不作为普通家园稳定产线；燃油和体力不再新增同名副本。

生产—远征—精炼—建设形成闭环：基础产出维持日常整备，搜打撤带回稀缺原料，工坊精炼和训练设施把它转成已有可消费物品，建造/驻军再消耗空间与资源。升级改变生产选择、可靠性、驻军/装卸能力与防御方向，而非全设施同比翻倍。

土地代价必须可见：工厂需要连续平地、道路与装卸面；商港需要临岸泊位；田地需要地块；山脊、墙和阵地占用这些位置，并可能延长运输。用山防守会减少可发展平地，但不额外给整个岛套任意产量百分比惩罚。玩家可以选择经济优先、滩头防守、纵深防守或机动驻军。

允许地形工程时先做草稿与预览，显示费用、施工时间、移除/搬迁后果，确认再提交。取消不扣资源。禁止一键免费把工厂地改成高山迎敌，禁止封死最后一条合法滩头—目标—撤离通路。

驻军使用真实有限的连队/预备队；同一连队不能同时出征和驻防。战壕按驻员开火，空壕不凭空生成兵。入侵先维持本地机器人岛，舰队起锚应战、陆军依托阵地；不宣称已接真人联机。掠夺仅涉及设计允许的暴露库存，保留角色、建筑等级与保底恢复资源，避免反复被打后无法恢复。无损本地演习不结算损失、维修、资源和奖励；录像只读，不重复发放战果。

## 7. 米制、方向与显示比例约定

- 原核平面 `x/y`、地图 `width/height`、建筑占地、舰体长度直接按米解释。`sea_map.gd:84—96` 不除以1000；千米只在标签层格式化。
- `sea_map.gd:340` 以 `hullLengthM/2` 画舰体线，世界航向方向为 `(sin heading, cos heading)`；屏幕投影翻转y。新3D不能拿屏幕向量当世界朝向。
- 当前Demo写明 Godot X向东、Z向北、Y向上。正式适配可按 `(core_x, height_m, core_y)`，但必须登记地图原点/偏移和模型“前方轴”；若采用Z向南方案则统一反号，禁止不同车辆自行修正。
- 镜头渲染可使用局部原点减去大世界偏移；命令和保存始终回到原核完整米制坐标。缩放只改相机，不改速度、射程、占地或实体位置。
- 现有家园标尺 `home_island_canvas.gd:441` 从1000m按视窗减半并标“m”。满级家园按既有实际8×10km；720×720m样区仅验证局部观感与同框比例。
- 玩家点击热区/SD最低屏幕高度是可读性辅助，不是实际身体高度。选中圈、脚底、碰撞中心和命令目标共同绑定真实实体；不要靠把坦克/楼再乘任意倍率去修镜头问题。
- 速度字段保留各原协议约定；海军航速不能把“节”直接当m/s。原创模式允许已登记的节奏改编，历史战役仍遵守RTS改编规范。

## 8. 下一步共享地理合同建议

下列为接口建议，不新增正式schema或替换现行核。若制作JSON设计稿，应单独使用 `visual_demo` 或 `proposal` 范围，不能命名成已发布v4权威数据。

| 字段族 | 最小信息 | 用途 |
| --- | --- | --- |
| 身份/版本 | `map_id, island_id, geometry_version, generator_version, seed, authority_scope, geometry_hash` | 多岛归属、冻结航次、缓存、回放与迁移核验 |
| 单位/坐标 | `units=metres, axis_convention, origin_m, bounds_m, sea_level_m` | 防止米/千米、南北与世界偏移错误 |
| 连续表面 | 原核确定的高度/水深样本或可重演参数、采样间距、插值约定 | 生成规则、渲染、实体脚点、坡度/视线共源 |
| 岸线与通行 | 带ID岸段、岸型、陆/水面、坡度、有效宽度、吃水要求、入口/出口连通 | 合法登陆、艇航路、普通/两栖/空中能力差异 |
| 语义地块 | 沼泽、道路、林地、灌木、岩地、悬崖、河流及真实占地 | 类型化移动、掩护、观察、工程和工事布置 |
| 人造设施 | 建筑/废墟/工事ID、米制变换、完整footprint、入口/路口、损毁状态 | 家园与战场一致、搜索与建设规则、有限驻防 |
| 只读视觉 | `visual_seed, biome_palette, weather_visual` 与独立资产映射 | 换素材/LOD/天气不改地理与战局 |

视觉网格可以使用不同分辨率，但要从同一权威表面生成；渲染碰撞不能私自重新用另一种噪声或重新抽随机数。若地形高度插值有误差，应登记误差上限并验证临界坡面、岸段和脚点，不能以“看起来接近”代替。

建议接入顺序：冻结现有版本 → 新原核合同和可重演地理快照 → 原核路径/岸型/建设预览 → 3D消费者与拾取 → 家园/海陆主小图切换 → 新航次搜打撤生成 → 结算与录像 → 手机验收。历史战役仅替换允许的显示层；原阵位、海图地标和卫星底图不得受原创岛生成器污染。

## 9. 中端手机的初始LOD方案

沿用总计划的待测预算，不把桌面截图当手机结论。建议以256m地形块管理，近景先加载3×3至5×5块，按投影屏幕像素而非单纯相机距离切换LOD。满级8×10km岛不常驻所有细网格、每株树与室内零件。

- 地形、碰撞/通行和视觉层分开：LOD只降细节，不删真实障碍、单位或合法岸段。远方仍保留原核模拟与海图标记。
- 树/石/灌木按地形块使用MultiMesh；不能把全岛塞入一个MultiMesh导致所有实例一起提交。建筑远景合并轮廓和材质，近景才加载屋顶小件。
- 手机优先不透明/裁切植被、单主光、少量阴影、有限粒子和避免全屏透明过绘；环境和载具的LOD依屏幕尺寸切换。
- 海面使用少量波层、共享低分辨率水深场及局部岸沫；远景停止高频岸边细节。首版不用全岛实时流体模拟。
- 同一时间只高质量渲染主地图，小地图降低分辨率和更新频率并停用细粒子；两者仍显示同一真实状态。
- 起始目标仍是720p渲染、30fps，p95≤33.3ms、p99≤50ms；可见三角形20—30万、环境不透明提交≤120/全帧≤300仅作初始上限。实际以设备实测、热稳态和内存为准，必要时降至10—18万面。

必须记录机型/系统/渲染后端，测试冷启动、30分钟热稳态、近岸集中登陆、密集楼群、炮击峰值、切海陆图、后台恢复及重复进出场景。未提供真机数据之前，Android与中端手机性能仍是未验收项。

## 10. 交付与阻断门

### 样区交付门

1. 相同镜头拍近、中、远景，至少含主滩、岩/崖岸、沼泽、山脊、街区十字路口和工事组合；视频显示10—20秒海浪与车辆转向/装卸。
2. 同框标尺板展示门洞、道路、艇、坦克、直升机、身体真实位置与SD外观。树不能穿楼、封道路或覆盖主要卸载面。
3. 演示普通艇与重型艇在合法/非法岸段的差异；明确标“样区演示”，不声称原核已执行。
4. 建筑、自然物、载具均有可编辑来源、许可记录和米制/pivot信息；美术不是扁图拼成固定照片。

### 正式接入阻断门

1. 同一地图/种子生成的地理哈希、岸段和建筑位置在原生/WASM、存读和录像重演中一致。未经测量不宣称跨平台确定性。
2. 海图、陆图、小地图和3D点选互相往返；地形临界点、模型脚点和真实命令目标误差有记录。普通艇不能越岛，装甲不能爬崖。
3. 同一拖动预览与提交的合法性/费用/载具/路线一致；取消不消费；切图不丢选择，不产生重复实体。
4. 家园新产线的每个输出有真实消费者，容量/离线结算/重复领取幂等；旧银币和岛屿补给不混账。纯美术展台不能通过经济验收。
5. 真实有限驻军、反甲小AOE、步兵清剿、独立车辆控制、无损演习与只读录像分别跑通；战损/掠夺/恢复不出现负数、无限生成和重复发奖。
6. 新号教学对应实际新机制：拖陆军卡到合法岸段 → 舰艇接近并卸载 → 清除孤立岸炮 → 装甲经宽滩上岸 → 步坦协同 → 观察/拖动舰炮支援 → 回收 → 回家完成一项生产和驻防。每步一次动作、一次反馈，详细数字按需展开。
7. 历史战役的阵位、海图、参战舰和规则回归通过；正式账户与旧航次可恢复；中端手机预算通过实测后才扩整岛。

当前已核对接口和文档边界；未在本文件执行原核回归、手机测试或新样区实景验收。主代理完成实景后应另记所用截图/视频、版本和发现，保留“已做”与“待办”分界。
