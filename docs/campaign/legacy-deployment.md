### 地图与机动

原版 §1.2（规则书 PDF 3、印刷 3）每格对边宽约 600 码、每回合三分钟。以相邻格中心相距 **548.64 米**构建连续平面。旧地图为平顶六角、奇数列下移半格；列序在 Z 后用 AA、BB……，不同于表格列编号。

以西南角为原点，东为 x 正方向、北为 y 正方向。对从 0 起算的列 `q`、行 `r`，令 `s = 548.64 m`，格中心为：

`x = s / √3 + q × s√3 / 2`，`y = (总行数 − r − 0.5 × (q mod 2)) × s`。

航向 1–6 分别换算为 060°、120°、180°、240°、300°、000°，沿任一旧相邻格的方向都与 CAS 的北向坐标一致。开局航速暂按每 180 秒走过相应格数换算；如旧航速 5 换算为 29.624190 节。换算表示在连续海图保留旧开局位移，并不授权高于 CAS 舰卡能力的航速；各舰待核实后决定开局速度。关卡时间同样只提供 `旧回合数 × 180 秒` 的 RTS 候选值。

四图的旧可航区域为 46×39，印刷区为 34×27；午夜决战为 92×78，约 43.87×43.07 公里。原引擎在十次开局均未放置陆地、海岸或雷达遮挡，且五关均无增援。现实海岸与亨德森机场只出现在原关背景，不把地名变成阻挡多边形、部署点或胜利区。

### 阵位和任务如何读取

- `ships` 保存完整旧开局阵位；`formations` 是旧定义的编队提案。未移动或旋转舰位，也未增设队列。所罗门 1928 有 15 个舰位与提案纵队不符；午夜决战有 75 个。没有同格部署。
- 午夜决战的 `post_default_formation_setup` 另存原引擎接受两方默认整列命令后得到的 16 支编队和 91 艘舰阵位；75 艘发生变化，整列后仍无同格部署。经典模式保留部署位置和提案，不执行额外整列。马里亚纳同时保存默认位置与自由部署的两条边界、严格半平面及交替顺序。
- `objectives.intent` 给出原任务和触发目的；`legacy_scoring_evidence` 保存旧版计分字面以供复核。旧损伤点、速度轨、火炮命中表、穿甲特例和雷达数值均不得参与 CAS 裁决。两场 1928 想定的首轮武器限制留待定义 RTS 时间窗。未有来源确认昼夜的关卡不写默认值。
- `campaign_detail` 用原战役 ID、旧想定 ID 或新想定 ID 返回 `legacy`；Rust 内核也可调用 `campaign::legacy_deployment(id)` 读取类型化几何。尚未绑定时期舰卡、环境和结算的五份记录均保持关闭出航。其余十一关继续取 CAS 原页数据。

`python scripts/import-legacy-campaign.py` 可离线检查五份输出的几何、方向、阵位和编队约束。加 `--ibs-worktree "F:/Codex/worktrees/android-mobile/铁底湾"` 可从固定 Git 对象重放两侧开局并逐字节复核；这一步需要 PyYAML 和旧引擎的 Python 依赖。重放不会改动旧仓。
