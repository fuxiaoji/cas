# 人机竞技大厅与真实流程验收

2026-11-12。本轮负责原生竞技大厅、编队肖像选择、段位徽记、段位奖励和最近对局界面。账户服务、原核规则及主界面接线由主代理和原核代理分别实施；不把静态菜单作为完整竞技证据。

## 界面

`arena_presentation.gd`的`render(app)`实例化`scenes/ui/arena_hub.tscn`。模式使用`arena_mode=ranked|team3`，两个页签分别保存选择和积分。左侧以原有密苏里完整插画的非破坏Atlas取景为主视觉，保留头部；原创罗盘/舵翼段位徽记按七档颜色与宝石变化。右侧是两列可滚动编队卡，使用本人立绘头像、编队名、实际舰数及CAS分值；卡片勾选最多四组，预算条清晰显示当前总分。排位10000分，3v3玩家席3400分、两支友军各3300分。

预算或身份不合法时禁用出击，错误原因就地显示；界面不绕过真实`arena_service`校验。段位奖励必须完成原核真正终局且历史最高分达标，认输不解锁初始奖励；已领按钮禁用。战报翻译实际win/loss/draw/forfeit，不自己计算胜败。大厅持续显示当前全部队友与对手为本地人机。普通上一层/母港导航与竞技入口由主代理统一加入。

## 真实验收

`godot/tests/arena_ui_review.gd`，Godot4.7.2 / RTX5070。初次使用隔离构建核；整合后无环境覆盖，直接以启动器最终默认ddf088…核复跑。

真实窗口最终 **51/51** 通过（原48项及3项AI队友操作边界）：

- 使用PID隔离新账户，测试档单独给六名不同DD以检查六编队滚动和1–4组选择，未改正常用户账户。
- 960×540、1280×720、1600×900、1600×720布局与出击按钮边界。
- 实际页签点击、四编队选择保存、第五组原服务拒绝、跨组重复身份禁出击。
- 两模式独立选择；实际出击按钮进入原核`new_arena`，AI进行真实航行/射击直到原核产生结果。
- 3v3原观察确认为两支友方AI与三支敌AI；敌人含实际BOT身份。
- 查看AI队友立即使海图和操作只读，原核也拒绝代控；重新选回玩家舰立即恢复操作。
- 实际结算页、积分/场次变化、清空活动航次、战报展示、段位按钮领取实际银币与元词、防重复领取。
- 关闭应用实例后重载，两个模式积分/最高分/胜败统计/已领奖记录严格相等。首轮发现JSON数值类型重载差异，主代理将服务输出整型统一后，以原严格Dictionary比较复验通过，未删除断言；before/after保留在回执`restart`中。

证据：`artifacts/godot/arena-ui/receipt.json`及14张实际截图。真实结果包括排位失利、3v3平局；未通过造胜利验证领取。
