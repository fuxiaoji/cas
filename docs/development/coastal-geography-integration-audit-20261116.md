# 连续海岸地理接入审计

日期：2026-11-16。状态：第1–7节记录最初只读审计；用户随后明确授权必要时从Demo重做，第8节追加显式连续地理候选实现与验收边界。旧v4、历史与正常发布入口没有因这次候选而迁移。Demo级画面仍需真实窗口评审，不以地理单测替代美术验收。

## 1. 结论与版本边界

可以把已批准的连续海岸、山体、低洼沼泽、河谷和有限沙滩带入真实原核，但需要新的地理合同。单纯让三维显示读取旧v4分区，再换材质和模型，不能得到Demo那种连续地貌。不得用客户端噪声填平这一差异，然后保留另一套碰撞和AI地图。

当前新增的 `src/geography_snapshot.rs` 只读导出既有地理，保持旧坡道/分区采样并明确未知项。它是共源接线的一步，**不是新的连续地形生成器或登陆裁决**。该模块不改变原生成、战斗、保存内容和历史数据。

截至本次审计的版本占用检查：

- `cas-island-war-v4` 是现有已发布原创岛战版本；正常入口仍由已验证发布清单控制，27人格目录和并行306草案保持原边界。
- `cas-island-war-v5` 仅见于经济建设设计中的预留建议，没有运行实现。不能直接把它当作已经批准的完整新规则。
- `cas-coastal-geography-v1` 在运行代码与规则文档中未占用，可作为下一阶段**候选**地理合同名；正式开工前应再次检查。
- 地理版本、战斗版本、经济版本和视觉资产版本应分别登记。不能仅换美术版本就自动迁移旧战局，也不能让旧录像在新地形上重新结算。
- 历史战役、旧岛战和已保存的旧航次保留原版地理、舰位、目标、表值与卫星海图注册。

## 3. 推荐的最小工程切分

建议新建独立的 `coastal_geography_v1` 模块，保存真实米制表面、地貌、水面、外轮廓和岸段。它不依赖Godot相机、着色器、模型LOD或天气显示。

为复用现有武器、独立人车、连队、载舰、航空和录像机制，可以给原创岛战增加显式新地理构造入口，而非复制整套上万行战斗引擎。需要评审的最小改动是：

1. `Geometry` 增加可选的新地理描述或共享采样场；原构造始终为空，旧方法原样执行。新入口才注入新表面。
2. 现有 `Battle::new` 保持原行为，增加独立的 `new_with_geography` 或等价显式构造；家园预览和战斗必须拿到同一份冻结描述。
3. `Terrain` 保留原regions，新规则才读取连续高度、坡度、软土和水深；旧版本不能自动启用新坡度惩罚。
4. 保存、加载、重演和预览登记新的战斗/地理身份，拒绝版本或哈希不匹配。旧v4入口和旧Saved验证条件不放宽。
5. `geography_snapshot` 对新合同增加明确分支，导出真实场；`observe`只引用静态地理身份，不每帧重发全岛高程。

这条路线仍需要改动少数现有类型和构造接点；“可选字段+显式新分支”不等于无需旧版回归。所有旧公开流、已登记原核/WASM重演和历史冻结门仍要重新通过。

另一条可评审路线是将Godot程序生成结果作为**明确的自定义地图内容输入**，由原核核验、接纳并完整冻结。这能先保持Demo构图，但必须验证尺寸、数据范围、外轮廓/水深一致、有效登陆与目标连通、设施占地以及快照哈希；保存完整地图内容，重演不再调用客户端随机数。它不能被表述成“原核已独立按种子生成”，也不直接满足未来服务器可信生成要求。本轮未选择或实现该路线。

不建议只复制Demo的 `height_at()` 调到Godot正式页面；FastNoiseLite的客户端结果不能成为另一套未经原核冻结的路径和碰撞真相。

## 4. 新共享数据的最小合同

| 字段族 | 建议最小内容 | 重要约束 |
| --- | --- | --- |
| 身份 | map_id、island_id、geometry_version、generator_version、seed、geometry_hash | 所有正式身份非空；每岛唯一；哈希用于缓存不冒充密码学签名 |
| 坐标 | units=metres、origin、bounds、sea_level、轴约定 | core(x,y)到Godot(x,height,y)，局部渲染原点只影响显示 |
| 表面 | 网格原点、间距、宽高、量化高度、水床或水面、固定三角插值约定 | 原核、渲染、脚点、拾取与路径采样同一表面；不能各自平滑 |
| 地貌 | 地貌格/分区、软土、水深、道路桥面、林地与掩护语义 | 外观与移动/观察后果一致，不能只涂沼泽颜色 |
| 岸线 | 外轮廓、带稳定ID岸段、岸型、海侧/陆侧方向、有效宽度、卸载与通路信息 | 岸段数量可变，禁止所有岛硬编码恰好三个滩头 |
| 人造地物 | 建筑/废墟/墙门ID、米制占地、入口、道路连接、地基与损毁语义 | 先验证真实占地和通路；模型底座不能代替合法性 |
| 只读视觉 | 视觉种子、调色、天气、资产映射和LOD | 波峰/云/模型细节不能改变地理和战局 |

建议量化高程并规定唯一三角划分，生成只做一次，身体每步采样为O(1)。8×10km范围若使用32m格，约8万高程样本；具体格距、整数范围、近岸加密方式和手机预算仍需实测。不能把这个估算当已实现预算或已经过手机验收。

## 5. 真实机制的接入点与失败风险

### 5.1 外轮廓和海深

新海岸必须同时进入海军 `naval.islands` 和陆军 `ground.polygon`。海图、陆图、家园、小地图与搜打撤不能各自生成一张近似岛。海面着色的浅水/碎浪也取同一水床或岸距数据。

地形海拔为负不自动代表任何舰船都能航行：吃水、可接近水路和安全余量需要独立明确规则。未实现时应阻断新消费者，不能直接返回绿色合法。

### 5.2 登陆与撤收

需要把 `Geometry::beach()` 及AI中多处 `1..=3` 替换为版本化的 `beach_ids()` 或带ID岸段查询；旧版返回原三点，新版返回实际有效岸段。预览、部署、普通艇抵近、重型艇卸载、两栖渡海、撤收与AI选择必须读同一结果。

普通艇只能岸边卸载，部队后续步行；两栖车辆水慢陆快，也不能爬垂直崖；旋翼/伞降飞越不等于任何地点都合法落地。有效滩宽、下船占位、队列拥堵和内陆通路应逐项加入，不能以单个地面点在岛内代替。

### 5.3 地面移动

`traversable / surface_disc / surface_path` 应由新表面提供坡度/侧坡/水深/地表成本，再叠加真实障碍和人车占位。现有river与ford/road优先关系必须保留或明示新规则变化，不能新水面覆盖桥面后把道路变成水沟。

应验证纯步兵、履带装甲、两栖和飞行对象的不同通行域。原核拒绝和界面预览拒绝必须一致；拖动组件不能继续无条件显示可部署。

### 5.4 高地与视线

新规则的LOS需要两端实际高度和中间采样高度，考虑身体/车辆观察点；不能沿用“经过cliff polygon就无限高遮挡”冒充连续地形。炮兵间接支援、航空与舰炮不能错误套用地面直射遮挡规则。此处会改变原创战斗决策，需要显式新规则并实战校验。

### 5.5 设施与土地

建筑占地、道路交汇、装卸面、围墙门洞和驻防入口先在米制地理中验证。允许地基整平时应作为真实地形工程/地图生成步骤，费用、工期与取消语义另按经济合同实施。禁止客户端把建筑周边山体压平，而原核仍保留断崖。

现有家园120m格地址可以保留为迁移映射；新实体不能因此变成120m高楼或600m道路。旧建筑地址迁移到新岛需要独立预览/确认策略，不能直接把旧账号岛面替换导致设施落水。

### 5.6 画面与比例

720m Demo不能整体拉伸成8×10km。应把它的局部地貌组织和材质风格扩展为多个真实片区：港镇、工业遗迹、林谷、沼泽、山脊、海崖和有限滩头。道路、楼房、车辆仍按米制；局部镜头保持Demo的细节密度，全岛镜头用LOD收敛。

脚点使用细表面、地面却渲染另一套粗插值时会再出现悬空。近景应同三角格或明确误差界限，平滑法线不能偷偷改变真实高度。天气和波浪继续为视觉，不以波峰抬高卸载门槛。

## 6. 建议分期与验收门

1. **合同与黄金小样。** 冻结现有发布输入；登记新版本和轴向；先让一个真实米制小区的原核表面、Godot地面、脚点、拾取、水床和岸线一致。对照已批准Demo实际截图，未达到审美就不向其他模式扩散。
2. **真实登陆小闭环。** 同一小区完成普通艇、重型艇、两栖和空输预览/部署/撤收；展示不能卸载的崖岸、窄滩和真实内陆道路，测试AI不会横穿陆地或卡泊位。
3. **新原创家园/岛战。** 扩到等级实际范围；加入设施地基与道路、有限驻防和攻防；旧v4存档仍走旧入口。不要先给全部旧战役换新图。
4. **多岛搜打撤。** 每岛稳定身份/原点，同一航次冻结同一地理；任务只生成在真实可达空间，带陆军才安排合适陆军目标；海陆主/小地图不重新抽种子。
5. **发布与移动端。** 原生/WASM逐字节重演、旧流冻结、真实拖动/托管/登卸载、存读/回放和多个种子通过；再进行中端手机实际性能、峰值内存、发热/长局及触摸验收。桌面RTX截图不能关闭手机门。

建筑、载具后续可按免费模型→Blender→Tripo继续细化，但模型精细度不能解决权威地理仍为台阶分区的问题。当前优先修正画面构图和地形共源，不能把这一项推迟到资产精修之后。

## 8. 用户授权从Demo出发后的实际连续地理候选

### 8.1 显式入口与输入冻结

采用独立战斗/存档版本 `cas-island-war-coastal-v1`，地理合同 `cas-coastal-geography-v1`，施工格 `coastal-construction-grid-v1`。旧 `cas-island-war-v4` 携带新geography会被明确拒绝；新规则缺完整geography也被拒绝。新保存保留地理输入，重演重建同一厘米量化网格。没有把旧120m地址转换为新36m地址，更没有修改旧账号。

首个地图来自已经批准的原Demo程序，原尺寸720×720m，不是静态照片、放大截图或新写的近似噪声。Godot只在创建内容时导出样本；Rust验证后的冻结格成为这场战斗的共同权威。输入文件 `godot/data/coastal-demo-v1-714.json`，原始SHA256为 `295a07aa1bc34a287dbfc505f4aaefd551aab817849ea32e35be06bed4324a02`。对应量化网格缓存身份 `fnv1a64:def8b4272dcb6ef2` 是便携非密码学身份，不是SHA256。

输入字段：

- `version/id/seed` 明确地图身份；`heightfield.origin={x:14240,y:12640}`，`cell_size_m=4`，`columns=rows=181`。
- `heightfield.heights` 是32761个逐行米值；导入后量化至0.01m。Demo原 `(x,z)` 加 `(14600,13000)` 成为原核 `(x,y)`，没有横向或纵向放大。
- `biomes` 同顶点数，限定 sea/sand/sea_cliff/swamp/river/mountain/forest/grassland；`water_levels` 同顶点数，无内陆水面用-100m哨兵。
- 每格固定三角 `a,b,c / b,d,c`，`u+v<=1` 使用首三角。高程、解析坡度、渲染与拾取必须用这一插值，禁止另加物理噪声。

正式候选只改独立source-27副本中的Geometry/base/wrapper/入口及新模块。共享原v4文件、并行MCP-306、原PDF、参考项目与正常已发布核不改。`src/coastal_geography_v1.rs` 为独立新模块；它不会被未接线的共享旧入口自行启用。

### 8.2 当前真正共源的消费者

验证网格边界为海床，从固定三角0m等值线生成740点闭合外岸，供原海军岛碰撞与陆地polygon共同使用。移动从同格高程/坡度/地貌取值；悬崖阻普通步兵、装甲和两栖车，陡坡分别按单位类别限制，河道水位阻普通人员/装甲、两栖保留低速，沼泽与森林有不同倍率。地面直射LOS真实穿采网格高程，低地不能隔着山岭直射；曲射保留原有绕过地面直射LOS的语义。

现复用战斗命令中的3个登陆编号，登记的是**三个真实沙滩泊位槽**，不宣称三处独立海湾，也不把全岸变成可卸载。泊位从沙滩、实际高程/坡度和海侧水深样本选取；重艇还需30m局部岸宽，普通槽最少16m。普通艇用海床/岸线局部航路绕陆，不再直线穿岛；身体在实际岸上可通行处卸下，不能在海上或内陆目标凭空出现。新岛初始驻防以真实HQ向内陆布置，逐身体独立碰撞落点，三个玩家卸载泊位100m以内禁初始驻防，避免把旧坐标回退成贴脸尸堆。以上新分支不改变旧v4。

Demo镇区、工业区与格街以原米制布局进入道路字段，逐2m核验中线和宽度两侧；实际948点为干地。道路仅标记 `surface_only`，没有速度奖励，也没有把跨水彩条冒充桥梁。街道平面相交会形成路口，视觉仍由Godot构建。

新家园36m格只开放20m包络内地面、水位、地貌和地基高差均合适的位置。当前720m首岛得到21个保守合法格，足够先验13类设施；这不是“满级大岛”已经完成。战斗设施按本人真实矩形地块+2m留隙判断重叠，取消新36m格受到旧65m圆距离误拒绝。旧v4保留原65m。新720m岛的夺点/敌方干扰分别24/40m，托管接近阈值12m，避免旧270m远控与100m外停步。

observe只携带地理轻头/id/hash，`geography_snapshot` 首次返完整格与静态设施；同hash可以缓存。详情查询的height/slope/biome/movement/landing来自真格，而不是旧分区。另保留静态场景身份与地形身份的区别，HP/tick不应令地形缓存失效。
