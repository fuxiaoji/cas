## 明确制作边界

1. 第一章回收与突围当前沿用固定五艘驱逐舰原生模板。神通、受庇护人类与运输船在剧本中表现，尚未加入这张模板的独立可操作护送对象；不能将对白当成新增实船或护送裁决。
2. 首次搜索回收的唯一MCP为成功战报后产生的故事保管记录。当前模板实际搜索目标仍为旧档案遗迹，未新增一件可在俄罗斯积木货舱中摆放的MCP实体物品。
3. 海陆教学真实借用舰艇与部队沿当前v4三课，不能将“信浓远距离支援”对白视为新增原生信浓航母或炮击实体。
4. 风暴迎敌当前为既有v4驻防演练。四重巡增援、重巡级怪物、乌龟山起身及密苏里救援炮击以剧情CG表现，尚未增加相应原生阶段、火控、伤害或敌人组合。真实迎敌成功先承认守住本轮，失败承认压退与救人，再接新增剧情威胁。
5. 第二、三章为现有作战模板承载新剧本，未将每段新目标名冒称全新原生任务。对话与剧情不改变历史战役、Rust裁决、原PDF或参考工程。
6. 章长约一小时为设计预算；工程验证会快进阅读，不等同真人一小时游玩验收。新增CG与动作素材是否齐备以最终美术清单和实际文件为准。

## 可编辑入口与验证

Godot新演出场景：`godot/scenes/ui/canon_story.tscn`，继承现有可编辑剧情舞台，预览章节/节点/行可调。演员节点持续存在；只更新当前文本与本人表情，不在每句话重建页面。未知战列舰与全息通讯只读取信浓本人剪影，缺图时不回退到本人公开头像或他人立绘。

专项脚本：`godot/tests/canon_story_v2_review.gd`。默认验证新目录、三章图结构、普通账号首段真实回收/搜索/存取；设置 `CAS_CANON_FULL=1` 继续全链。测试只创建 `artifacts/story-canon-v2/runtime-*/ordinary.json`，不读取用户活动航次作为测试输入、不操作用户窗口。最终通过范围以该次回执为准，不把代码检查视为完整玩法验收。
