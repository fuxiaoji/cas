# 海陆空协同 v4：原海图操作与陆空拖卡

当前是联调记录，尚未登记正式默认核验收。历史战役及已保存的两栖 v1–v3 没有升级为新规则。新航次海战使用原 World、原指挥界面及真实炮雷/雷达系统；航空和陆战仍是单独登记的原创玩法，不声称实现完整 CAS 航空规则。

## 操作与版本边界

- 新 `littoral_naval_controller.gd` 复用 `legacy_battle.gd`，`littoral_world_sea.gd` 继承原 `battle_map.gd`。原选舰、编队、跟随/同步航线、航速、舰况、炮雷瞄准和射程/雷达范围仍读取 World 公开态和原命令。共享 HUD 只新增缺省不启用的两栖布局入口；共享地图新钩子在旧路径为空。
- 底部追加本人战术卡和真实母舰航空中队。军牌编制标记按登记番号/明确 echelon 显示旅 X、师 XX、团 III、营 II；不从本航次连数、身体数或协议上限推算。
- 陆战卡拖岛屿由原核验证舰种资格、真实位置、运力和近岸/空输距离，再投送。已登陆卡拖空地移动、敌体/敌设施攻击、遗迹搜索；公开实体的实际坐标优先于表现散开坐标。楼体/岩石落点明确拒绝，不能把公开不可走地形画成绿色合法地面。
- 舰艇向岛内拖动登记真实岸援炮向；陆图支援卡实际训练炮座并消耗原炮位的装填及弹药。射界外仍须正常航行调整，不瞬转舰艏或只设置 UI 的“已对准”。
- 航空卡拖敌舰、地面、敌机分别下达真实 ship/land/aircraft 任务。原核决定甲板串行、有限武器、实际飞行、命中、损失与返航。鱼雷机攻陆被原核拒绝；指令受理不等于命中。召回不会把在空飞机直接删掉。
- 海/陆主副图可以交换。海图保持原世界顶视坐标；陆图是统一等距投影。小海图不继承主图的平移像素，避免切换时裁掉整个作战区域。开场镜头包含实际舰队、岛岸与公开敌舰，随后仍可正常平移、缩放和拟定航线。

## 高度与点击

`littoral_land.project_base/unproject_base` 保留可逆等距平面。最终连续高地模型 `inset_edge_blend_v1` 按原核公开的 `height_m × clamp(距边界内距 / blend_width_m, 0, 1)` 计算，重叠区取最高；推荐坡道不覆盖该高度。显示采用真实 1.0 倍竖向抬高，人物、建筑、路径、投放点和命令共用。早期没有模型号的纯表现夹具保留原平台/坡道分支，不用于当前实战。

`unproject` 对新模型沿屏幕射线二分求解可见连续地面。80 米高地 / 120 米过渡带的最大高度梯度为 2/3；射线方向为 `(1,-1)`，高度变化率不超过 `sqrt(2) × 2/3 < 1`，避免早期 3.5 倍夸张引起地表折叠和拖点错位。几何缓存到观察变化，避免每次绘制反复构建多边形。

全岛概览按真实米制 fit；远景设施用 6–10px 标记，近景才按公开占地/宽度绘制，不设巨型楼图下限。每个真实身体仍单独显示和命中，概览约 8–12px，街区约 20–28px；保留 28px 操作命中范围。街区键聚焦所选队约 700 米，允许最高 12 倍，同键返回概览，并随独立 UI 状态保存。小岛 fit 留白随实际多边形大小调整，大岛保留最多 180 米边缘。原生岩石阻挡用同一占地的碎石场表达，不以深色方块覆盖地面。固定整岛照片不参与地图。

## 伤亡与美术

永久尸体只来自 v4 公开 `littoral.corpses`。五名已登记本人各有三种原创倒姿，`pose_seed` 稳定选择自己的图格；其他本人缺少独立 SD 时继续本人肖像兵牌，不借别人的脸。旧 v1–v3 的四秒倒地表现维持原行为。正常 returning/recovered 不被当成死亡；倒带到死亡前删除未来尸体，恢复到死亡后直接显示已落定姿势，不重新开火/受击。

`combined_arms_art_preview.tscn` 可在 Godot F6 预览五人十五倒姿、四类原创岸敌与八个航空型号。区域直接用 Atlas 元数据；源像素不程序裁改。新贴图已导入 MIP，动态云雨层保留。街区/高度材质由独立 `procedural_amphibious_terrain.gd`/`procedural_town.gd` 消费原核几何绘制，不改变碰撞。

## 独立行动连与绘制预算

新请求显式使用 `company_layout: multi-company-v1` 时，每个真实连单独一张卡，`company_id` 管指令、`unit_id` 管本人人格与美术。卡常驻显示人格名、完整番号和「一连 1/5 · 9人」，横向滑动只滚动卡列，往地图拖动才发实际命令。选中连单独高亮，移动、技能次数、载舰、登陆、撤收和保存都使用该连 ID；不会将五张卡指向同一组状态。没有该开关的旧单连观察即使含 `company_id`，仍使用原 `unit_id = group.id` 接口，避免缺少新字段而报错。

合法五人格最大组合的实际验收为 21 连、181 个友方身体，未将 250 的预算上限冒称已测身体数。全岛视角逐体兵牌和街区选中连本人 SD 使用有上限的表现散开，世界位置、射程和指令坐标保持原核值；每个实际身体都保留独立命中目标。局部 y 排序只在人物容器内进行，不让演员层盖过海图、顶栏或拖卡。

街道、地形、高地和碎石采用独立静态 Canvas，只有原核几何、尺寸、镜头或缩放变化才重画；敌我身体、真实弹道、云雨和海岸泡沫继续按模拟时钟更新。海岸动态独立绘制，不以冻结海面换帧率。非选中小兵牌不随无关待机帧重复生成绘制命令。此优化仍保留同步原核桥接和完整海军 HUD 的耗时，性能记录明确包含更新峰值。

## 阶段证据与未完成的门

`artifacts/littoral-v4-ui/` 记录隔离账户与原核真实请求。所有正常用户主/备账户只读；直接请求的 UI 夹具不冒充拥有/采购流程，正常账户和搭载资格由独立账户验收覆盖。

- `world/`：原海图三尺寸、范围、航线、真实舰炮/鱼雷、舟艇/空输落地、地面拖动、正常回收、航空出击/返航及完整关核恢复。
- `aviation/`：正常 raid 真实敌航母提供空中目标，分别实际拖攻陆/舰/空，错误兵种目标不扣武器，真实武器发射、飞机数量守恒和恢复。
- `casualties/`：弱编队合法战斗中的真实伤亡、本人不同倒姿、长期留存、完整恢复与回放。
- `training/`：只按照可见手势及实际目标中心操作，不通过隐藏命令替代玩家；完成门为真实成功撤离。
- `components/`：纯表现夹具含旧投影冻结、三尺寸/主副图/缩放的平面及高地坡道逆变换；不当作真实战斗证明。
- `companies/`：21 连/181 真身体的三尺寸、逐体命中、卡列横滚、同人格不同连独立移动、技能仅该连扣次、关核保存恢复与 1×/8×实测帧间隔。
- `company-landing/`：真实两张同人格连卡分别投送，各有九个本人身体；只撤回第一连，第二连留岸，第三连未部署。恢复后正常回收不产生尸体。
- `layout-fixture/` 与 `art/`：分别是明确标记的纯布局/美术门；不能冒充 v4 原核游玩。

当前阶段候选不等于最后默认安装产物。扩大岛屿、真实高地及最新原核冻结后，需要更新实际三尺寸、完整三课和有限性能取样，并登记正式 runtime SHA。Windows GPU/触摸事件注入不等于手机实机；网络对战和完整 CAS 航空推演也不在本次完成声明内。
