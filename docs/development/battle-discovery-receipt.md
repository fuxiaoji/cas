# v2 射程与残骸工具验收

`godot/tests/battle_discovery_review.gd` 使用独立临时账号和真实 `cas-sim.exe`，通过 Godot 输入事件操作按钮；不改权威位置、库存或舰卡。生产代码由主集成修改，本测试线仅新增验收脚本。

窗口验收 **56/56**，5 张 3840×2160 实际全屏截图；随后加入“搜空后底部按钮同步且禁用”断言，最终无窗 **52/52**。34 次按下/抬起事件。数据位于 `artifacts/godot/battle-discovery/receipt.json`、`receipt-headless.json`、`window.log`、`headless-final.log`。

通过的行为：

1. 射程默认开启，底部直达按钮与“视图→射程/雷达”操作同一状态；两个入口的勾选文字同步。开关不改变原核观察。
2. 进入真实夜战雷达教学，通过实际设备按钮开雷达；选中舰的炮、雷、雷达半径均来自当前原核观察。截图 `01-selected-gun-torpedo-radar.png`。
3. 正式经济入口提交显式 `salvage-v2` 航次，默认显示 4×。残骸搜索列表严格等于本席已发现残骸，不列隐藏目标。截图 `02-known-wreck-list.png`。
4. 点击残骸条目选中其真实 ID，并将该已知位置放到海图中心；不修改世界状态。截图 `03-wreck-located.png`。
5. 真实舰艇满足 750 米和 8 节条件后，点击情境按钮开启原核 6 秒搜索。2 秒时重复点击不重置计时；完成后真实货舱增加，计时清空。截图 `04-native-collecting.png`。
6. 已搜空残骸在搜索列表中禁用；最终追加断言确认底部情境按钮变为“已打捞”且禁用。截图 `05-collected-wreck-and-cargo.png` 展示完成列表。

预验发现的两个界面同步问题均由主集成修复并复验：视图菜单切换没有更新底部射程文字；完成打捞后底部仍保留旧指令。没有发现原核重复发货或状态泄漏。
