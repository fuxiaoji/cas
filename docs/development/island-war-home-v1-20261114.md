# 家园攻防与战术整备 v1

本轮 UI 与账户闭环以保住亲手建立的岛屿、选择舰队与登陆编制、带回实际物资为目标。岛上继续直接点设施、拖动落位；新增岛务入口收纳人机海域、仓储与录像，主画面不增加常驻数据表。所有入侵明确为手动开启的本地人机模拟，没有联网玩家、离线袭击或伪造录像。

## 版本与归属

- `home_service.gd` 委托 `home_development.gd` 管理本人养成和岛屿发展，委托 `home_island_war.gd` 处理独立 `new_island_battle / cas-island-war-v1`。旧 `new_littoral / cas-littoral-v1..v4` 请求及战损规则保留。
- 新原核统一导出 `data/island-war-v1.json` 六座岛的实际守舰、陆军规模、设施布局和仓储，界面不另造敌人阵容。
- Main、战斗控制器和只读录像播放器由 root 接线；Rust、守军和塔型裁决由 littoral_autonomy 实现。本代理不修改历史舰表、原始 PDF、正式账号或用户窗口。

## 岛屿与仓储

联络中枢 1–5 级解锁真实更多可建格，指挥官等级分别限制后续扩建（3、6、10、15）。旧账号建筑原位保留，不迁移或删除；外圈尚未开放时不能确认建造。中枢扩建同时提高设施总容量，新增近防机枪、曲射迫击、海防导弹和战地整备节点，原核决定实际射击/修复，不以文字冒称生效。

浮材、合金、岛屿补给、协议片有安全保管量；仓库及中枢等级提高保管量，能源不参与掠夺。安全量外仅 20% 进入本场风险池，并设每资源 1500、协议片 30 的上限。预览与开始时冻结同一数额；实际原核 `island_war.outcome.plundered` 不得超过它，防御仅扣实际失守数额。母港基地仓库的实物和当前舰队货舱与岛屿生产资源继续独立。

## 二十本人养成与身体整备

二十个稳定 MCP ID 各自具有 Lv1–30、两阶突破和原核公开枚举内的专精。达到 Lv10/20 后需相应指挥官等级及资源突破。等级在新岛屿规则下满级约提高 5% 耐久/火力，不进入历史或冻结 v4 战斗。战后经验来自实际终局并按本人发放，不因多连重复。

身体库存以实际 company layout 为有限先遣编制，例如 MCP-034 为五连×九人。1000–6000 是世界观中协议完整编制上限，不等于免费身体储备。实际原核本人战损落入整备率并从终局时重新起算慢恢复；每 30 分钟恢复 1%，医疗站加速。升级/突破/专精均不治疗战损。

手动补员用整备目标滑块，先展示本人、有限人数、缺损身体等值和能源/合金/岛屿补给费用。确认后在同一个账户事务扣除并补到公示目标；取消不扣费，重复事务不再扣费，行动中禁止补员。训练、突破与专精采用同一事务约束。

## 完整攻防记录

保留最近八场完整本地记录：初始请求、初始快照、终局快照、快照内真实指令数组、规则与核心版本、本人战损、资源收入和仓储损失。旧简要记录没有完整证据时明确不可回放，不补造过程。回放由独立 CoreBridge 只读执行，观看不触发战斗结算，不改变正在进行的行动。

接线：`home.prepare_island(mode,npc_id,units,ships,preset,transports)`；`home.begin/settle` 按规则版本委托；`home.replay_record(run_id)` 返回 `{ok, record}`；`home_conflict_ui.gd.open(app,"records")` 打开列表，按钮调用 `app.open_home_replay(run_id)`。

## 验证

验证只使用新建隔离普通账号并注明赋予测试资源，覆盖二十身份、有限先遣人数、真实预览/扣费/取消/幂等、升级不回血、突破与专精门槛、中枢实际扩格、仓库保护增长、存读及旧身份迁移。GPU 使用实际窗口输入并保存不同尺寸截图，正式主备档 SHA 前后核对。原核候选安装完成后另验证真实攻防终局与录像完整性，不把尚未运行的新战斗登记为已通过。
