## 可编辑性边界

1. 四个场景有真实运行节点，布局编辑可以保存重载。母港按钮、肖像和活动主要分区可以在 2D 编辑器选中。
2. 母港设置 `Use Default Styles=false`，补给卡设置 `Use Default Style=false` 后，可以保留节点自定义字体、颜色和 StyleBox。副本分别写入 39 号字、紫色文字和自定义色块，保存、重载及 `_ready()` 后均保留。母港八个图标已直接引用真实 SVG 资源，关闭默认样式也保留素材。
3. 补给卡设置 `Use Catalog Content=false` 后，可以保留自定义标题、金额文案、价签和插图；保存重载已验证。默认目录模式的 `pack_id` 有即时刷新 setter，运行中更换为 `demo-980` 后立刻显示 `980 元词`。显示编辑不修改实际订单目录的数值。
4. `godot/data/liveops.tres` 现在是优先活动内容源。其标题、副标题、两张 CG、公告子资源的标题与正文均可在 Inspector 修改。复查只改深拷贝资源并保存重载，真实 ActivityHub 显示新标题、副标题、CG 与公告；源文件 SHA256 和缓存的原资源均未改变。修改内容资源后重新加载场景即可读取新值。新增公告可复制现有公告子资源，保留 `liveops_announcement.gd` 的字段结构。
5. 当前项目保持 1600×900 逻辑视口，再缩放到窗口。三种窗口均无入口越界，2:1 窗口会横向伸展；宽屏重排尚未完成。
6. 活动 `Side/Wide` 详情节点仍在运行时创建，未将这些生成节点作为场景-owned 内容保存。公告和主要活动美术/标题可改资源；详情排列、按钮生成及部分固定介绍文字仍由脚本控制。不能称全部活动内容都已成为静态可视节点。

以上为后续可改进项，不构成本批新增页面的功能阻断。模拟充值的发放、重复请求与持久化事务由主代理的专项验收负责，本审查没有替代其经济验收，也没有使用原玩家存档。
