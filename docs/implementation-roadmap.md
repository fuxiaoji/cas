# CAS 后续实施与验收计划

从[接手说明](handoff.md)恢复主仓、待合并工作区和测试环境。以下各阶段是实施顺序。每条必须从实际玩家入口打通并留下证据，阶段结束后继续下一条。更新 `plan.md` 与 `havedone.md` 时区分源资料已核、代码已合、游戏内实测、双端验收和对外开放。规则工作、战役录入、外层迁移与线上服务可用独立工作区并行，共用协议、稳定 ID、规则版本和验收种子。

## 1. 恢复可构建主线和线上闭环

1. 先修 [已定位的 TypeScript 错误](handoff.md#一小时内恢复开发)，跑浏览器的 01／03 双线结局、本机抽卡、序章夜战和固定约战。随后合入两份未提交的服务差异，每条单独回归。线上抽卡使用服务端现有双池、专用券、三档保底和稳定请求编号，UI 只播放真实到账记录。按原 0.6.11 的主题图、概率页、十连、逐舰揭示、跳过、历史回看和兑换恢复 `OnlineSupply`。完成后分别验重复请求、刷新、换池、重登、短屏和余额对账。
2. 排位前端扩展 `OnlineDuelLobby.tsx`、`OnlineFleetEditor.tsx` 和 `main.tsx`。展示 3000／10000 两档、当前赛季和本账号段位、可用舰队、实际点价、入队、取消、重连、战果及分差。排位页只接受服务器认可的预设，战局中的 AI 风格冻结，建议需要本人确认。`status=complete` 且因服务故障作废时可能没有引擎 `result`，界面仍要停止操作并显示作废、积分不变。
3. 核对排位分支当前协议再接线。已对齐的接口是 `GET /pvp/ranked/status`、`POST /pvp/ranked/queue {request_id,budget,fleet_id}`、`POST /pvp/ranked/queue/cancel {request_id}`。战局复用 `/pvp/matches/{id}` 及命令、预览、战报、投降子路径。拟定的状态有 `available_budgets`、`point_table_version`、`season`、`ratings`、`historical_ratings`、`queue`、`matches`。排位战果含 `budget`、`season_id`、`own_fleet`、`fleet_cost`、`rated` 和仅本席的积分变化。以实际合入代码与测试更新契约。
4. 用两全新账号从序章获得免费舰并建预设。`FLETCHER/PERKINS/MAURY` 的已核时期包在 3000 分点表共 1875 分，原作同舰籍镜像可用。实际匹配、下令、互射、重连、正常终局、投降、平局、服务器异常作废和重试入账各验一次。参考 0.6.7 原排位为每账号、每赛季、每分档独立，起分 1000，K24，400 分尺度，42 天 UTC 赛季，等分正常胜负 ±12。旧版 150 秒是回合封存超时，RTS 中先保留掉线重连，回合封存条款的实时等价处理另作明确改编并独立验收。
5. `data/rules/cas-competitive-points-v1.json` 由原生 `match_pool` 导出，点价由核验舰卡参数与 CAS RTS 竞技系数计算，只有 3000 分在候选开放列表。原生 `match_new_ranked` 也能构建含北卡罗来纳／大和的 10000 分真局，但服务尚未开放。3000 分先做多种子、换边、免费对稀有舰队与实战重演。10000 分先做约战，补齐战列舰炮组和必要规则、舰卡取得路径与平衡后，再开放独立赛季。每场冻结开局舰队、领舰、AI、版本和点价，队列中途改预设要有明确规则。保留固定 5 对 5 作为非排位模式，同时补 3000 分个人舰队非排位。

## 2. 完成水面 CAS 裁决并扩展其余章节

以 [CAS 五版覆盖台账](rules/coverage.md)为逐条清单。每条同时交付原页、时期数据、入口、规则编号、正反边界、至少一个实际想定消费者与重演。先完成会阻塞剧本的机制，再补其余平台和想定。扩展伤害表与可选规则注明启用范围，保留想定特例优先。

| 施工线 | 下一步与验收 |
| --- | --- |
| 航行与舵 | v8/v9 已用 CAS 舰卡的标准舵前进距离、转向失速与加减速，做圆弧航迹。先核主规则 §3.1.4 和损伤章节，补满舵、最小可转弯尺度、卡舵状态与强制运动、修舵、倒车／紧急制动。核岸线碰撞、搁浅和舰体接触，区分预览告警与实战裁决。用同一初始编队实测领舰经过同转向点、同步各自转向、换路、重整、领舰失能、全队降速及受损舰脱队。 |
| 主炮与次要武器 | 核 §6.1 的火力组、不同指挥仪、局地控制、反应半伤、火力过集中、炮口与陆地遮挡、轻防空对海及小艇适用规则。保留 CAS 命中、射程、穿深和伤害。把原 180 秒的表伤预算按实际可用炮管和装填周期分摊，额外射击动画不能增加掷骰机会。各炮座随时期表绑定横转与装填史料，区分实测、手册机械上限、炮族估计和暂定调度参数。当前弗莱彻 4 秒有同级舰炮位记录，18°／秒仍暂定，多个舰型尚需逐座补证。炮弹飞行当前由 CAS 射程反推有效速度，继续核对应炮弹的历史弹速或实测弹道；动画与落点时间随权威实体。相关证据见 [实时主炮台账](rules/realtime-gunnery-sources.md)。 |
| 鱼雷 | v9 已支持 §6.3 的直航实体、尾迹、深浅航、单座部分齐射、左右舷防护。下一步优先加 `TorpedoMount.reserve` 及本舰实际再装填状态，核案上备弹、运输改装、可重装条件、所用时间与失效时点。支持塔萨法隆格资料中的两艘各 8 枚备用雷，原页未定座位或时长时记录出处与待裁决项。补发射窗内一次合法转向与随后直驶、雷速／航程档、艉窄向指定临界、变航、音响制导、反制、潜艇与航空雷。放雷和命中仍走 CAS 射向、交会、舷向、概率及实际命中时刻，取消、无合法目标或失效不得扣雷。见 [v9 定深台账](rules/torpedo-depths.md)。 |
| 损伤和损管 | v7 起，炮弹在实际弹着秒累积 CAS 临界阈值，每目标每窗一枚数量骰，达到新增临界即执行。同秒齐射统一先结算普通伤害，已离膛的炮弹继续飞行。补舵、舰桥、发电、通信、各类装备、弹药库波及、持续沉没、倾覆及完整损伤表。并行验证水下／炮击临界、战损舰炮塔与航迹、同秒公平和旧档规则冻结。 |
| 观察和夜战 | 依 §5 继续补探照灯、目标照明、逐步识别、雨阵／烟幕和地形遮挡、火控雷达各型号、炮闪、岸基和空中观察。区分本舰直达雷达解算、友舰共享和目视目标，界面与 AI 共用过滤。先覆盖瓜达卡纳尔、萨沃、霍腊纽等历史需求，固定夜战教学增加真实新规则的实操。 |
| 航空、潜艇、岸防、水雷 | 建 §4 航空平台、编队、任务、高度、飞行甲板、机场与可核飞机卡，再接 §5 感知、§6 防空与反潜、§7 空战和空袭。潜艇同时补 §3 航深与航行、声呐、深弹／前投武器和反制。§9 岸防与设施需地图目标、岸炮、结构与胜负，§10 布雷／扫雷需海域、器材、触发和隐藏信息。每个系统做实际开局、交战、战果和保存恢复。 |

每次改变裁决创建新规则快照，旧版本按原数据、原随机流和原时点重演。Windows 和 Android 用同一 Web 客户端与 WASM，线上用同源 Rust 原生。正式服需按已冻结哈希运行在途旧局，匹配时固定核心版本。客户端的预览、AI 建议、战报、录像、重连均从本席观察生成，射程圈不探出隐藏舰，敌雷尾迹从首次被观察的位置开始。

## 3. 让全部 32 个中文战役关位可玩

当前 01 通道行动、03 圣乔治角、04 库拉湾的双线共六关可出航，其余 26 关是档案。11 个同一历史交战、5 个旧作部署迁移方案均已登记。原手游的关位、解锁、难度、评级、奖励、旧剧情与背景继续使用稳定 ID。历史版的阵位与胜负按 CAS 想定，架空版的阵位与任务按旧作，舰艇仍绑定 CAS 时期配置。内容和中文名称分层，原文只用于内部出处。

| 关位 | 录入安排 |

## 4. 补齐原手游外层、演出与音频

- 按原版本对照登录、母港、值更舰、角色收藏、编队预设、剧情解锁、历史借舰与个人舰队分流、教学复习、越级挑战、活动中心、邮件、商店、双池双券、保底、礼包、兑换、赛季和战绩。逐个核实际入口与条件。0.6.11 的离线行为和 0.6.7 的线上行为分表登记。补正式池所有符合 CAS 的舰卡、原奖励与售卖资格。第七日北卡罗来纳现为预览锁定，待同一稳定 ID 的出战、资产和跨端验证通过后再启用，验证已拥有时重复奖励的原规则。周本沿用每周三次、每次两张常驻券，并与权威每周实战任务分别验账。
- 序章目前是 15 艘舰实战，已可见双方战列线交火和实际鱼雷，第 204 模拟秒交接第五驱逐小队。继续对照原手游大舰队开场约 96 艘舰的编制、演出节奏和镜头，按可执行的 CAS 舰型扩编，给真实对局打性能基准。保持原剧情与分支、原新版弗莱彻立绘、同图对白、不换海图背景和逐按钮演练。固定敌方战列线与我方战列线交战，为驱逐舰制造侧翼雷击机会。验收录像须能看见真实炮弹、鱼雷、弹着和从大场面推近小队。可在表演编队使用剧本状态机，所有实弹仍走战斗裁决。
- 序章逐步引导选领舰、画多航点、同步机动、炮击、调角放雷、取消及接管。独立夜战课固定开局、敌舰航路和教官顺序，验证本舰开机、直接回波、共享回波差别、目视识别、照明和真实战报。课程完成以实际命令或引擎事件认定，避免把点击演示或随机命中设为唯一门槛。
- 保留三种首批指挥风格并完成原手游其余指挥官与均衡守势、自适应、两翼夹击等行为。敌方配置独立，挑战无需拥有该 AI。自动托管分机动、炮击、鱼雷，手动接管持续到明确交还。按本席同一合法命令生成建议；批量换边验证接敌距离、目标选择、雷击和撤退差别，不能只改显示名。
- 按旧事件与稳定角色 ID 继续迁战场语音、指挥官专属录音、序章 BGM 和战斗配乐。当前为 16 段旧通用电台与五段原创配乐，专属语音、原曲授权和其他立绘仍待核。按序章开场、交火、命中、损伤、沉没和指挥动作触发音频并去重，配乐给对白和语音让音。所有图、声、背景和录音保留来源与分发范围；原《战舰世界》曲库需核授权方可随独立发行包分发。缺授权或缺原文件的具体条目留可验清单，不能标为已完整还原。

## 5. 最终发行验收

1. 原页录入校验、完整 Rust 和服务回归、新旧版本存档、原生／WASM 对照及玩家视角过滤全部通过。抽查命令被拒、瞄准失效、压缩战报和动态接触消失，确认隐藏状态不泄漏。场景覆盖表、舰型时期表和规则表每个缺项都有明确决议和实战证据。
2. Windows WebView2 和 Android 实体机分别从新账号验证登录、母港、序章、教官、领取、征募、组队、出航、战果、恢复。覆盖横屏短屏、触控中断、切后台、Esc、炮雷同时可用、取消不耗弹、应用重启。另用同版本 Windows 与 Android 线上互打，验证跨端重连、两席命令、自己的报告及一次性评分。
3. 验双档编制、免费舰队强度、重试与并发幂等、邮件、领奖、抽卡、季末归档、无效局作废。先免费内测，之后按原产品交付范围核支付渠道、订单、退款及发布素材。另验 iOS 的范围按原计划后置。独立安装包、账号、存档、钱包和战局不得覆盖铁底湾项目。
4. 发布前保存每个包的版本、构建提交、签名、SHA-256、资源账本、性能报告、实机录像和关键对局回放。在 `havedone.md` 标出每项实际证据和剩余差额。交付判定看完整 CAS 改编、全部旧剧本、原手游外层与两端联机是否一并验收。
