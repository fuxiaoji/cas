# RTS 改编工程规范

本规范适用于所有 CAS 想定的引擎、数据、客户端和战役接线。RTS 改编的目标是**拟真**：把原书的 180 秒裁决拆成逐秒操作，但不改变原书给定的舰队、阵位、数值、概率和胜负条件。任何为了界面、性能或旧海图而删除编队、挪动舰位、压缩距离、改表值的做法都视为缺陷。

## 一、原书硬约束（不得删改）

1. **编制**：舰名、舰级、数量、编队/纵队序列、旗舰、可选增援都必须按原页登记。基础编成里原页没有的舰不得加入；原页有的舰不得因为缺数据而静默删除，只能标为 `source_only` 并阻断出航。
2. **阵位**：原页给出的方位、距离、航向、航速和相对基准（如“在 X 舰右舷艏 5,000 码”“Y 在 Z 的 295° 方向 18 海里”）必须按原值计算。不得用近似坐标代替。
3. **环境**：光照、能见度、云量、降水、海况、风、月相按原页；缺字段就登记缺失，不得用默认晴朗海况顶替。
4. **目标与特例**：双方胜利条件、任务、撤离线、登陆/运输、先验损伤、侦察机、雷达/探照灯实装等逐项保留；未实现的项必须在源笔记和运行时的 blockers 中显式登记，不得静默省略。
5. **数值**：舰卡、炮表、鱼雷表、损伤表、探测表、雷达表只按已核页录入；RTS 改编只能改变时间粒度和操作方式，不能为了平衡改表值或删修正。

## 二、海图与尺度

1. 海图必须容纳原页的接敌距离。**不得为了适配旧海图压缩阵位距离**；应扩大 `Field` 并在客户端调整初始视野/缩放。
2. 原页指定的地标、岸角、岛屿、锚地必须落在海图上，并与评级几何使用同一坐标；不得只留一个不可见的数值点。
3. 海图边界、岛屿和浅水必须参与航行/视线裁决；新增地标不得遮挡原页没有遮挡的射界。

## 三、未印值的处理

1. 原页没有印出的量（例如列内舰间距、个别炮座转速、未给日期的雷达型号）只能使用**一个全局登记的默认值**，不得每个剧本临时臆造。
2. 默认值必须写进源笔记的“原页值 → 运行时值 → 状态”表，注明“原页未印，采用 X 作为默认”，并接受后续实舰证据替换。
3. 任何近似、压缩、替代或未实现项都必须在该想定的源笔记中有一行记录；没有记录就不算完成。

## 四、运行时验收

1. 每个想定必须具备：原页核对表、舰卡/炮雷数据、运行时开局、双方 AI 或玩家可完成一局、原生 vs WASM 逐字节重演、浏览器真实点击验收。
2. 战斗结果必须能回到原页的胜负条件；如果数值上无法复现历史结果，登记为平衡偏差并说明原因，不得改原页条件迁就结果。
3. 修改引擎前先读 `agent.md`、`plan.md`、`havedone.md` 与对应源页；不得修改原始 PDF 或参考项目。

## 五、评审门

新增/修改一个想定时，评审必须逐项回答：

- 原页舰名、序列、航向、航速、方位距离是否逐项对上？
- 海图是否包含原地标，尺度是否容纳原页距离？
- 缺失/近似/未实现项是否都在源笔记里？
- RTS 改编是否只改时间粒度，未改表值和概率？
- 是否有真实对局、原生/WASM 对照和浏览器验收？

任何一项答不上来，不得标记为“剧本验收通过”。
